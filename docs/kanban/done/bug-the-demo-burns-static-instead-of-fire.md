# bug-the-demo-burns-static-instead-of-fire — The demo burns static instead of fire

Reported by ear, which is the only instrument that could have caught it: the demo scene's
audio "is just static". It was, and the file responsible had been in the tree for six hours.

## What was wrong

`build_fire_crackle` in `scripts/make_test_scene.py` synthesised a four-second fire loop for
the braziers G9 builds in code. Its own docstring claimed "a **low roar**, filtered noise
around 90 Hz, which is the bulk of it and the part that reads as heat rather than as
static". Measured, it is the opposite:

| | synthesised | the recording beside it |
|---|---|---|
| zero crossings/s | **10,451** | **1,064** |
| high-frequency ratio | **0.40** | **0.02** |

Broadband hiss wearing an envelope. Four sources played it continuously, so the demo hissed
from four points in the room.

## Why it was written at all, which is the part worth keeping

**A recording of a fire was already in that directory** — `fire_crackle.m4a`, 71 seconds,
present since two days before. Nothing read it, and the row that needed a fire wrote a new
one from scratch rather than reaching for it.

The instruction that produced it said *"any new asset must be generated by
`make_test_scene.py`, never downloaded"*. That is a misreading of the convention, which is
that assets are **fetched or generated** — `fetch_assets.sh` exists to do the fetching, and
both asset trees are gitignored precisely because their contents arrive rather than being
committed. "Not committed" became "not downloaded" became "synthesise", and each step looked
like the previous one.

There was a second reason to reach for synthesis and it should have been *reported* rather
than routed around: **the engine cannot decode the recording.** miniaudio reads WAV, FLAC and
MP3; `fire_crackle.m4a` is AAC in an MP4 container. That is presumably why it had sat unread
since it arrived, and it is a real finding — it just is not a reason to invent a replacement
without saying so.

## What no check could see

Nothing in this repository can hear. The golden set compares pixels, the readback compares
texels against a source file, the unit suite never opens a device, and the verification
scripts now pass `--audio-null` specifically so they make no sound. G9 verified this asset
by running the demo for 400 frames with validation layers on and reporting zero errors —
which was true, and said nothing about what came out of the speakers.

The gap is not worth closing with a machine listener. It is worth knowing that **the audio
path's only real check is a person**, and recording that here is the fix available.

## The fix

`transcode_fire_crackle` replaces `build_fire_crackle`: eight seconds cut from ten seconds
into the recording, mono at 48 kHz, quarter-second fades so the loop join is silent, `volume`
rather than `loudnorm` — single-pass `loudnorm` on a source this quiet (mean −41 dB) returns
digital silence, which the first attempt at this produced and which measured as cleanly as
the static did.

When ffmpeg or the recording is missing it writes nothing, deletes any stale output, and says
so. The demo already tests `Resources::found()` before building the source, so the braziers
burn silently — which is the right failure. A fresh clone has no audio at all today;
`fetch_assets.sh` fetches only Sponza.

## Verification

- `scripts/readback.sh release` — 9 of 9 bit-identical plus the lit silhouette. This matters
  more than it looks: `make_test_scene.py` also regenerates `readback.png` and `cutout.png`,
  so a non-deterministic edit to that script would move every readback case.
- A validation-layer run of the demo scene, headless, 90 frames — zero errors, and the log
  reports `4 crackles` built.
- Measured: 1,064 zero crossings/s and a high-frequency ratio of 0.02, against the
  synthesised 10,451 and 0.40.

One readback run reported `1 case(s) failed` with every case printing `ok`; the intermittent
`VK_ERROR_DEVICE_LOST` three cards recorded today. Two clean runs bracket it.

## Outcome

Fixed as above. `impact.wav` was measured and left alone — 275 zero crossings/s and a
high-frequency ratio of 0.03, which is a thud; synthesis was the right call for a
quarter-second transient with no recording to hand.

The instruction that caused this is corrected at its source: assets are fetched *or*
generated, and an asset that already exists is neither. Where an existing asset cannot be
used, that is a finding to report, not a reason to quietly write a replacement.
